# Battery Brightness

Brings back separate screen brightness for **plugged in** and **on battery**, which older versions of Windows had. It can also switch the refresh rate when the power source changes, for example 120 Hz when plugged in and 60 Hz on battery.

It's a tray app: one ~70 KB `.exe` for Windows 10 and 11, with nothing to install (it uses .NET Framework 4.8, which is built into Windows).

## Using it

Run `BatteryBrightness.exe`. A sun icon appears in the notification area. Click it to open the flyout:

- **Plugged in / On battery sliders.** The brightness for each power source. The highlighted row is the one in use now, and dragging it changes the screen right away. Dragging the other slider only stores the value for next time.
- **Remember changes made outside this app** (on by default). If you change brightness with the brightness keys or the Windows quick settings slider, that becomes the new value for the current power source, the way old Windows behaved. Changes made by battery saver aren't remembered.
- **Switch refresh rate with power source.** Pick a rate for each source, or "Don't change". When you first turn it on, it picks the fastest rate for plugged in and 60 Hz for battery. If there's more than one display, you can choose which one it controls (the built-in panel by default).
- **Start with Windows.** Starts the app in the tray when you sign in.

Right-click the tray icon for **Exit**. If you run the exe again while it's already running, it opens the flyout of the running copy.

> On Windows 11, new tray icons start out hidden behind the `^` overflow arrow. Drag the sun onto the taskbar, or turn it on under **Settings > Personalization > Taskbar > Other system tray icons**.

There's no way to add a page to the Windows Settings app itself. Third-party apps have no extension point there, so the tray flyout is the closest substitute.

## Building

You need the .NET SDK (any version from 6 on). Building doesn't need the .NET Framework 4.8 developer pack, because the SDK fetches the reference assemblies from NuGet.

```bash
dotnet build -c Release
```

The output is `bin\Release\net48\BatteryBrightness.exe`. That file is all you need: copy it anywhere. The `.exe.config` next to it is optional.

`app.ico` is generated by the app itself. To redraw it after changing `Icons.cs`, run `BatteryBrightness.exe --write-icon app.ico` and rebuild.

## How it works

| Piece | How |
|---|---|
| Power source | `GetSystemPowerStatus`, checked on every power broadcast, on resume from sleep, and every 5 seconds as a backstop |
| Brightness | WMI `WmiMonitorBrightnessMethods.WmiSetBrightness` (`root\wmi`), the same interface Windows uses for built-in panels |
| Remembering changes | WMI `WmiMonitorBrightnessEvent`. For 3 seconds after a power switch or resume, any level Windows restores is overridden instead of being remembered |
| Refresh rate | `EnumDisplaySettings` / `ChangeDisplaySettingsEx`. The built-in panel is identified through `QueryDisplayConfig` |
| Settings | `HKCU\Software\BatteryBrightness` |
| Start with Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, entry `BatteryBrightness` |

## Limitations

- Brightness works on displays that expose WMI brightness, which means laptop and tablet built-in panels. External monitors (DDC/CI) aren't supported. Refresh-rate switching works on any display.
- With **Change brightness automatically when lighting changes** (adaptive brightness) turned on, Windows keeps changing the level itself, and the app would remember those changes. Turn off adaptive brightness, or turn off "Remember changes made outside this app".

## Uninstalling

Turn off **Start with Windows** (or delete the `BatteryBrightness` value under the Run key), exit the app, delete the exe, and optionally delete `HKCU\Software\BatteryBrightness`.
